# T008 – Workflow und Statusmodell

Status: `done`. Grundlage T002/T006/T007; keine Auftragsausführung.

## Umsetzung

`domain/workflows.py`, `application/status_service.py` liefern versionierte
Vorlagen für Figuren, Effekte, statischen Inhalt und Dokumente sowie einen
reinen Resolver. Eingabefingerprints, exakte Build-/Revisionsbindung,
Sperrgründe, Pflichtkriterien und Invalidation sind von Qt und Ansicht getrennt.
Die konkreten Verträge sind in MODELS.md beschrieben.

## Tatsächlich geprüfte Abnahme

41 Studio-Tests bestanden, einschließlich aller Workflow-Fälle:
externe NPC-Quellen fehlen ehrlich; statische Inhalte ohne Framepflicht;
`skipped` bleibt blockiert; failed/cancelled/running/passed bleiben getrennt;
falsche Build-Bindung ist kein Erfolg; eine neue Quelle macht Nachweise stale,
verändert aber nicht das historische Evidence-Objekt; unpassende Maskenbindung
ist stale; pauschales done überstimmt keinen Pflichtfehler; illegale
Nachweiszustände werden abgelehnt. Layout-/Namensänderungen invalidieren
keine Pixel und verändern den Status nicht.

## Grenzen und Übergabe

Der Statusdienst zeigt noch keine Pipeline-Erfolge, weil deren Ausführung
erst später implementiert wird. Fehlende Vorgänger werden konkret benannt.
Alle Tests sind Qt-freie Core-Tests; keine reale Sicht-/Godot-/Runtimefreigabe
wurde erzeugt. T009 kann die Projektdaten und Diagnosen ehrlich darstellen.
