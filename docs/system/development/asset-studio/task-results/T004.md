# T004 – Katalog und Migrationen

Status: `done`. Grundlage T003; technische Dokumentation: DEVELOPMENT.md.

## Umsetzung und Dateien

`storage/sqlite_repository.py` und `storage/migrations.py`: SQLite mit
aktivierten Fremdschlüsseln, kurzen serialisierten Schreibtransaktionen,
Schema 1→2, konsistentem Backup vor Migration und optimistischer
Revisionskontrolle. Immutable Revisionen sind nicht editierbar. Archivierung
ist logisch; es wird keine Datei gelöscht. Layoutdaten liegen separat.

Portabler, deterministischer Metadaten-Snapshot mit explizitem Import nur
in einen neuen Katalog. Prüfungen, Freigaben und Deployments aus fremden
Snapshots werden nicht als erfolgreiche Nachweise übernommen. Exportierte
Revisionen referenzieren Bytes; der Snapshot enthält keine Originaldateien.

## Tatsächlich geprüft

26 Tests im Studio-Lauf, davon Katalogprüfungen in `tests/test_storage.py`:
Transaktionsabbruch ohne halbe Objekte, aktivierte FK-Constraints, veraltete
Bearbeitung mit Konflikt, Archivieren/Wiederherstellen, Migration mit
erhaltenen IDs/Dokumenten, absichtlich fehlerhafte Migration mit intakter
Sicherung, Export-/Import mit identischem Assetbezug, beschädigte Kataloge.
Alle bestanden. Grenzen/Startbefehle sind in DEVELOPMENT.md dokumentiert.

## Abnahme, Schutz und Übergabe

Katalog- und Migrationskriterien erfüllt; keine laufende DB wird versioniert.
Tests erzeugen ausschließlich temporäre SQLite-Dateien. Einzelbenutzer,
kein gemeinsam beschreibbares Netzwerkprojekt. T006 baut hierauf fachliche
Hierarchieregeln auf; der Storage-Layer allein ist kein Workflow-Editor.
